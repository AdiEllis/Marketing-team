# Even & Etz AI Marketing Studio: היתכנות, ארכיטקטורה ותוכנית

> **עדכון 08.10.2026:** בעקבות התשובות שלך, הארכיטקטורה שונתה למודל ללא עלות. הסוכנים רצים בתוך Claude Code, ואין שרת או API בתשלום. ראו `docs/decisions.md` (ADR-001 עד ADR-004). הארכיטקטורה המלאה למטה נשמרת כאופציה לעתיד, אם ירצו אפליקציה עצמאית.

> שלב 0: תכנון. **עדיין לא נכתב קוד.** המסמך עונה על סעיפים א–ז במשימה הראשונה.

## א. סיכום הבנה

מערכת Web בעברית, מותאמת לטלפון. את מעלה תמונות וקליפים אמיתיים של עבודת נגרות, וצוות סוכנים מנתח את החומר, מציע רעיון שיווקי אחד מנומק לאישורך, מפיק בפועל (בלי לדמות) סרטון ראשי, פוסט ושני תוצרים מזוויות שונות, מעביר הכול בקרת איכות, מציג לך, מקבל תיקונים ממוקדים ומוסר קבצים מוכנים להורדה עם טקסטים לפרסום.
העקרונות: **נאמנות מוחלטת למוצר**, **רעיון לפני הפקה**, **אפס עלות בהתחלה** ו**שקיפות** לגבי מה הופק בפועל.

### ⚠️ השערות שצריך להוכיח ב-PoC
- **Parallax 2.5D** (תחושת עומק מתמונה אחת) עם מודל עומק פתוח על CPU: איכות ללא עיוותים בקצוות המוצר?
- האם סרטון שנבנה מסטילס ועוד 1–2 קליפים אמיתיים מרגיש "פרסומת" ולא מצגת? **זו שאלת הליבה של ה-PoC.**
- זמני רינדור על המחשב שבו המערכת תרוץ.

### 💲 דורש תשלום או חומרה
| יכולת | למה |
|---|---|
| **הנפשה ריאליסטית מתמונה** (דלת נפתחת מתמונת סטילס) | **אין היום פתרון חינמי, אוטומטי ואמין.** Wan 2.2 פתוח אבל דורש GPU חזק (או דקות ארוכות ולא יציבות ב-Colab חינמי). Veo, Kling ו-Runway: תשלום לשנייה. ויש בעיה נוספת: גם בכלי בתשלום, AI "פותח" דלת על ידי **המצאת** תוכן פנימי, וזה אסור לפי כללי הנאמנות. |
| **קריינות עברית טבעית** | לא מצאתי מנוע חינמי שמותר לשימוש מסחרי ונשמע טבעי. Phonikud: לא מסחרי. ElevenLabs חינם: בלי זכויות מסחריות. |
| הפעלת סוכני ה-AI מתוך האפליקציה | קריאות למודל (Claude API) עולות כסף לפי שימוש. ראו שאלה 1. |

### 💡 ההמלצה המרכזית: "הנפשה אמיתית" במקום הנפשת AI
הדרך האיכותית, החינמית והאמינה ביותר להשיג פתיחת דלתות, מגירות ותנועה היא **קליפים קצרים אמיתיים** (3–5 שניות בטלפון) שמצולמים בזמן ההתקנה. הסוכן יפיק **רשימת שוטים קצרה** לכל פרויקט. זה בדיוק מה שהופך את סרטון הגרביים של Riviera לחזק: אפס AI, חומר אמיתי ורעיון טוב.

## ג. ארכיטקטורה מומלצת

```
 [ממשק Web בעברית, Mobile-first, PWA]
            │ HTTPS
 [API: FastAPI (Python)] ── [PostgreSQL: פרויקטים, נכסים, גרסאות, סטטוסים, משוב, פרומפטים]
            │                         │
 [Orchestrator: מכונת מצבים]   [תור משימות על Postgres (Procrastinate)]
            │                         │
   ┌────────┴────────┐        [Workers ברקע]
   │   AI Layer       │          ├─ ניתוח מדיה (Vision)
   │ ממשק ספק אחיד     │          ├─ רינדור וידאו: HyperFrames (Node) ו-FFmpeg
   │ פרומפטים בגרסאות   │          ├─ רינדור פוסטים: Playwright
   │ JSON Schema       │          ├─ QA טכני
   │ Tracing ועלויות    │          └─ ספקי AI עתידיים (מתאמים)
   └─────────────────┘
 [אחסון קבצים: ממשק S3. מתחיל בדיסק מקומי, ניתן להעביר לענן]
```

### בחירות טכנולוגיות, ולמה
| רכיב | בחירה | יתרון | חיסרון | חלופה שנשקלה |
|---|---|---|---|---|
| Backend ו-Workers | **Python + FastAPI** | הכי חזק בעיבוד מדיה ו-AI (תמונה, עומק, Vision), SDK רשמי לכל ספקי המודלים | שני Runtimes (Python, ו-Node עבור HyperFrames) | TypeScript מלא: אחיד, אבל חלש בעיבוד תמונה ו-ML |
| מנוע וידאו | **HyperFrames + FFmpeg** | HTML/CSS שסוכנים כותבים היטב, עברית RTL מושלמת, דטרמיניסטי, Apache-2.0 | פרויקט צעיר (v0.8), ודורש בדיקה ב-PoC | Remotion: בשל, אבל רישיון "Automators" בתשלום. MoviePy: חלש בטיפוגרפיה |
| DB | **PostgreSQL** | אמין, JSONB ל-Specs, משמש גם כתור משימות | עוד שירות להרים (ב-Docker זה פשוט) | SQLite: מספיק ל-PoC, ובו נשתמש בשלב 1 |
| תור משימות | **Procrastinate (על Postgres)** | בלי Redis, Retries, נעילה נגד כפילויות, חידוש אחרי קריסה | פחות מוכר מ-Celery | Celery + Redis: רכיב נוסף בלי צורך |
| Frontend | **Next.js (React) כ-PWA** | Mobile-first, RTL, נגן וידאו, העלאות מהטלפון, ו"התקנה" למסך הבית | — | אפליקציה נייטיב: מיותר בשלב זה |
| אחסון | **ממשק S3, מתחיל בדיסק מקומי** | מעבר לענן בלי שינוי קוד | — | — |
| שכבת AI | **ממשק ספק אחיד**. ברירת מחדל Claude (Vision ו-Structured Output) | החלפת מודל בלי שבירה, פרומפטים בגרסאות ב-Git, תיעוד כל קריאה | — | — |
| פריסה | **Docker Compose** | אותה מערכת בפיתוח ובייצור. סביבות dev ו-prod נפרדות | — | — |

### מבנה פרויקט (מתוכנן)
```
agents/          מפרטי הסוכנים, ובהמשך prompts/ עם גרסאות
knowledge/       זיכרון מותג, ניתוח השראות, ספריית "אהבתי"
docs/            החלטות (ADR), מחקר, תוכניות
backend/         api/, orchestrator/, agents_runtime/, schemas/, workers/
render/          HyperFrames: ספריית Moves, תבניות פוסטים
frontend/        Next.js PWA
poc/             סקריפטים של שלב 1
```

### אבטחה (בקצרה)
התחברות פרטית (את ומשתמש נוסף אם תרצי). מפתחות API במשתני סביבה מוצפנים, ולעולם לא ב-Git. בדיקת סוגי קבצים לפי תוכן (לא לפי סיומת), ומגבלות גודל. הסרת מיקום GPS מתמונות לפני שליחה לספקים חיצוניים. גיבוי יומי של DB ואחסון. מחיקת פרויקט כולל מדיה לפי בקשה. מדיה של לקוחות **לא נשלחת לשירות ששומר אותה לאימון**.

## ז. שאלות פתוחות (רק מה שחוסם החלטות או את ה-PoC)

ראו את ההודעה בשיחה. השאלות מרוכזות שם.
